変更内容を確認し、コミットしてください。$ARGUMENTS

## 手順

1. 以下を並列で実行し、現在の状態を把握する
   - `git status --short`
   - `git diff --staged`
   - `git diff`
   - `git log --oneline -10`（既存のメッセージ傾向を確認）

2. コミット対象を決める
   - staged な変更があれば、それだけをコミット対象とする（`git add` はしない）
   - staged な変更がなければ、未追跡ファイル含む全変更を対象とし、`git add` してからコミットする
   - どちらの場合も、対象に `.env`、鍵ファイル、認証情報、巨大な生成物・ビルド成果物が混ざっていないか確認する。混ざっていればコミットせず報告する

3. 変更が複数の関心事にまたがっている場合は、コミットの分割案を提示してユーザーの判断を仰ぐ
   - 承認されたら、`git add` で対象を絞りながら複数コミットに分けて実行する
   - 単一の関心事であればそのまま1コミットにする

4. コミットメッセージを組み立てる
   - 形式は `prefix: 内容` のみ。本文・フッターは付けない
   - prefix は `add`（追加）/ `fix`（修正）/ `update`（更新）/ `remove`（削除）/ `refactor`（リファクタ）/ `docs`（ドキュメント）から、変更の実態に合うものを選ぶ
   - 内容は日本語で、何を変えたかが一読でわかる簡潔な一文にする
   - 例: `add: 管理画面の実装`

5. コミットを実行する
   - `Co-Authored-By` や `Generated with Claude Code` などの署名・フッターは一切付けない。コミット者は `git config user.name` / `user.email` の設定値のままとする
   - コミットメッセージの引用符やエスケープに注意する

6. `git status --short` で結果を確認し、コミットしたハッシュとメッセージを報告する

## 禁止事項

- `git push` は実行しない
- MR / PR の作成は実行しない
- `git commit --amend` や `git reset` など既存履歴を書き換える操作は、ユーザーから明示的に指示された場合を除き行わない
